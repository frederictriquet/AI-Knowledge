# 🧑‍💻 Generating code with AI

> **Objective guide (L3)** — a path that cuts across themes to answer: *how do you produce code effectively with AI?*
> This page brings together the **concepts/practices** (path below) and the **tools** (section at the bottom of the page).

## In brief

Writing code is no longer the bottleneck: the agent produces a lot of it, fast. The work shifts toward **framing, orchestrating, and above all verifying**. Using AI well to code means designing the **system** around the agent (the context, the loop, the guardrails) and keeping **understanding** of what is produced — not steering every line.

## Suggested reading path

1. **Shift your stance** — the center of gravity moves from writing to verification and judgment. Start with [Agentic code review](../concepts/agentic-code-review.md), then [Comprehension debt](../concepts/comprehension-debt.md) (the risk not to give in to), and [Loop engineering](../concepts/loop-engineering.md) (designing the system rather than prompting by hand).
2. **Understand how the agent codes** — [the canonical agent architecture](../concepts/canonical-agent-architecture.md), [CodeAct](../concepts/codeact.md) (code as action space), the [agent-computer interface (ACI)](../concepts/aci-agent-computer-interface.md) and the [Deep Agents](../concepts/deep-agents.md) pattern.
3. **Frame & decompose the work** — choose the right shape with [workflows vs agents](../concepts/workflows-vs-agents.md) and the [workflow patterns](../concepts/workflow-patterns.md), then break it down via the [decomposition techniques](../concepts/decomposition-techniques.md) and [prompt chaining](../concepts/prompt-chaining.md).
4. **Orchestrate multiple agents** — when scaling up to a fleet: [orchestration types](../concepts/orchestration-types.md) and [multi-agent structures](../concepts/multi-agent-structures.md).
5. **Verify & make reliable** — the core of the job now: [heterogeneous reviewers](../concepts/heterogeneous-reviewers.md), [Chain-of-Verification](../concepts/chain-of-verification.md), [eval-driven development](../concepts/eval-driven-development.md), [Reflexion](../concepts/reflexion.md) and [static vs dynamic human-in-the-loop](../concepts/human-in-the-loop-static-dynamic.md).
6. **Keep control** — [deterministic hooks vs probabilistic memory](../concepts/deterministic-hooks-vs-probabilistic-memory.md) to anchor invariants outside the model's judgment.

### 🧱 Agent fundamentals
- 🔴 **[ACI: designing the agent-computer interface](../concepts/aci-agent-computer-interface.md)** — give as much care to tool definitions (names, descriptions, formats) as to prompts: the agent-computer interface (ACI) is, for an agent, what the human-computer interface is for a person.
- 🔴 **[The 5 composable workflow patterns (Anthropic)](../concepts/workflow-patterns.md)** — a catalog of composable patterns, from simplest to most complex, to assemble yourself rather than delegate to a framework.
- 🔴 **[Workflows vs agents: Anthropic's architectural distinction](../concepts/workflows-vs-agents.md)** — distinguish **workflows** (LLMs and tools orchestrated by predefined code paths) from **agents** (the LLM dynamically directs its own process), instead of calling everything "agentic".
- 🟡 **[Deep Agents (pattern)](../concepts/deep-agents.md)** — an agent architecture pattern for **long-horizon** tasks: instead of a simple "think → call a tool → observe" loop, it combines **explicit planning + sub-agents with isolated context + a file system as external memory + a detailed system prompt** to go the distance without saturating the context.

### 🧠 Reasoning & planning
- 🟡 **[Chain-of-Verification (CoVe)](../concepts/chain-of-verification.md)** — the model writes an answer, derives factual verification questions from it, answers them in isolation, then corrects its answer in light of those checks.
- 🟡 **[Self-reflection / Reflexion](../concepts/reflexion.md)** — after a failure, the agent writes a critique of what went wrong and replays the task with that critique kept in memory.

### ✍️ Prompting
- 🔴 **[Decomposition techniques](../concepts/decomposition-techniques.md)** — explicitly break a complex problem into simpler sub-problems, then solve them one by one, to make the final answer more reliable.
- 🟡 **[Prompt chaining](../concepts/prompt-chaining.md)** — breaking a complex task into a sequence of simple prompts where the output of each step feeds the next.

### 🔧 Tools & function calling
- 🔴 **[CodeAct (code as action space)](../concepts/codeact.md)** — the agent emits **executable Python code** as its action, instead of rigid JSON tool calls.
- 🔴 **[The canonical framework: Agent = LLM + Planning + Memory + Tools](../concepts/canonical-agent-architecture.md)** — the reference decomposition of an autonomous agent: an LLM plays the role of the brain (controller), supported by three components — planning, memory and tool use.

### 👥 Multi-agent
- 🟡 **[Multi-agent structures: hierarchical / holonic / coalition / team](../concepts/multi-agent-structures.md)** — four ways to organize agents: a chain of command, a whole-and-part arrangement, a temporary alliance, or an interdependent team.
- 🟡 **[Types of AI agent orchestration](../concepts/orchestration-types.md)** — four ways to distribute decision-making across agents: a single leader, a leaderless collective, hierarchical layers, or organizations that collaborate without sharing data.

### 📊 Evaluation
- 🔴 **[Agentic code review: from writing to verification](../concepts/agentic-code-review.md)** — When agents generate code faster than anyone can read it, the bottleneck moves from writing to **verification**: review becomes the highest-leverage skill, and the human shifts from "in the loop" to "on the loop".
- 🔴 **[Eval-driven development](../concepts/eval-driven-development.md)** — Building an evaluation system specific to your domain is the foundation of an AI product: it creates the data → evals → improvement flywheel and unlocks everything else.
- 🟡 **[Heterogeneous reviewers: low overlap between tools](../concepts/heterogeneous-reviewers.md)** — AI code reviewers overlap very little: rather than hunting for "the best" tool, run several with complementary strengths, like an ensemble.

### ⚖️ Governance, alignment & ops
- 🔴 **[Loop engineering: designing the system that prompts the agent](../concepts/loop-engineering.md)** — The leverage shifts from prompt engineering to *loop engineering*: instead of prompting the agent by hand, you design an autonomous system that discovers the work, distributes it to agents, verifies, documents and decides what comes next — with no human between cycles.
- 🟡 **[Comprehension debt & cognitive surrender](../concepts/comprehension-debt.md)** — the faster an agent loop ships code you did not write, the wider the gap grows between what exists and what you understand — a "debt" that, ignored, slides toward "cognitive surrender".
- 🟡 **[Deterministic hooks vs probabilistic memory (Skills / Memory / Hooks)](../concepts/deterministic-hooks-vs-probabilistic-memory.md)** — For a coding agent to honor a rule, the mechanism matters more than the wording: an instruction in memory (CLAUDE.md) is **probabilistic context** the model *may* follow, whereas a **hook** is a shell command run deterministically at a lifecycle point, which *guarantees* the action whatever the model decides — hence the triad "Skills = advice, Memory = reminder, Hooks = law".
- 🟡 **[Human-in-the-loop: static vs dynamic interrupts](../concepts/human-in-the-loop-static-dynamic.md)** — two LangGraph mechanisms to insert a human in the loop: predetermined breakpoints around a node (static), or an `interrupt()` call triggered from inside a node based on state (dynamic).
